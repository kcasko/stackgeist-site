## LinkedIn (career/IT hiring audience)

I got StackGeist from 81 to 100 mobile Lighthouse in two PRs.

The whole 19-point gap came from one thing: hero images were huge PNGs served without a priority hint. LCP was 4.9 seconds on mobile.

Two moves:
1. Wrote a Node/sharp script to generate AVIF + WebP siblings for the 4 hero images at the sizes actually rendered.
2. Swapped `<img>` for `<picture>` with proper `<source>` order, then marked exactly one image `fetchpriority="high"` and lazy-loaded the rest.

Result:
- Homepage: perf 81 -> 100, LCP 4.9s -> 1.5s.
- Setup pages (SetupHero component): perf 81 -> 99, LCP 5.0s -> 1.7s.
- Worst PNG (657 KB) drops to a 7.9 KB AVIF at the size it actually renders. 99% reduction.

Zero framework changes. TBT and CLS were already 0 (Astro's islands architecture pays off). The fix was one component refactor and one sharp script.

The lesson isn't "use AVIF." It's: when Lighthouse tells you one metric is failing and the rest pass, don't scatter effort across preconnect hints and font tweaks. Fix the one thing.

## X thread (dev audience, 8 tweets)

1/ Got a site from 81 to 100 mobile Lighthouse in two PRs. Whole 19-point gap was one thing: LCP.

Here's the pattern for Astro + Cloudflare sites serving heroes from `/public/`.

2/ Baseline (headless Chrome, simulated 4G):
- Perf: 81
- LCP: 4.9s (score 0.29)
- FCP, TBT, CLS, Speed Index: all green

That shape = your bundle discipline is fine. One image is holding the score hostage.

3/ Diagnosis: hero PNG was 449 KB, LCP `<img>` had no `fetchpriority`. Browser didn't know it was the LCP; discovered it late; downloaded it slow.

The other cards on the grid were also `loading="eager"`, competing with the actual LCP for bandwidth. Classic overshoot.

4/ Fix, move 1: generate AVIF + WebP variants next to the originals. `public/` files stay pass-through; sharp emits siblings at 400w / 800w for cards, 600w / 1200w for full-width hero.

    budget-gaming-desk.png  448.8 KB -> 4.0 KB AVIF (400w)
    small-bedroom.png       656.9 KB -> 7.9 KB AVIF (600w)

5/ Fix, move 2: `<img>` -> `<picture>` with AVIF first, WebP second, raster fallback. Explicit `width`/`height` on the fallback so CLS stays 0.

    <picture>
      <source type="image/avif" srcset="..." sizes="..." />
      <source type="image/webp" srcset="..." sizes="..." />
      <img src={fallback} width="800" height="450" ... />
    </picture>

6/ Fix, move 3: only the FIRST card is `fetchpriority="high"` and `loading="eager"`. The rest are lazy.

Marking every hero eager without a priority is worse than marking one eager. You need the hint OR nothing — a stampede is the worst outcome.

7/ Result:
- Homepage: perf 81 -> 100, LCP 4.9s -> 1.5s
- Setup pages: perf 81 -> 99, LCP 5.0s -> 1.7s
- TBT and CLS still 0

Two PRs, one component refactor, one sharp script. No framework changes.

8/ Field data (CrUX, Cloudflare RUM) aggregates 28 days, so ranking impact takes 3-4 weeks to show. But the lab number moved today.
